# Lightning OPD

## 标准opd流程

**先对学生模型做 SFT，得到一个 SFT 模型，然后再对这个 SFT 模型做 OPD。**

我之前可能把两个阶段的时间顺序讲混了，现在用最直白的时间线重新说一遍。

---

## 完整流程就是一个“两步走”

假设你手上有一个 **Base Model**（基础模型，比如 Qwen3-8B-Base），智商高但不会聊天、格式烂。你的目标是把它训练成数学推理高手。

### 第一步：SFT（监督微调）

**什么时候做？** OPD 之前。

**做什么？**
你用强大的**教师模型**（比如 DeepSeek-R1）生成一堆高质量的“数学题 + 标准答案（solution traces）”。

然后，你用这些数据去微调 **Base Model**，得到一个 **SFT 模型**。

**为什么必须做？**
Base Model 直接做强化学习/蒸馏很难。它连答案格式都不稳定，教师很难打分。SFT 让模型先学会 **“抄格式、抄基本解题套路”**，给第二步打好基础。

**产出：** SFT 模型 + 一堆“教师生成的标准答案数据”。

---

### 第二步：OPD（在策略蒸馏）

**什么时候做？** SFT 之后。

**学生是谁？** 第一步产出的那个 **SFT 模型**。

**做什么？**
1.  SFT 模型针对题目，**自己生成**一些新的 rollout（自己动脑想答案）。
2.  **教师模型**实时检查这些学生生成的 rollout，给每个 token 打分（这个 token 想得好不好？和我想的有多像？）。
3.  SFT 模型参考教师的打分，自我更新。

**痛点是什么？**
第二步训练时，**教师模型必须一直在旁边实时打分**，这非常烧钱（需要一直跑着一个巨大的教师模型服务器）。

---



## Lightning OPD 的优化，也是针对第二步

Lightning OPD 的思路是：

“我能不能**不做**第二步里的‘实时找老师打分’？”

做法就是：
- 回到**第一步**，在用教师模型生成那些“数学题 + 标准答案”时，**顺便把教师模型在每一个标准答案 token 上的 log 概率也存下来**。
- 然后到了**第二步 OPD** ：
    - 学生模型还是自己生成 rollout(**相当于第一步和第二步都是同一份题目**)。
    - **重点：** 不用再实时问老师了。直接把学生生成的 rollout，去和**第一步存好的那个“教师标准答案 + 教师 log 概率”** 做对比、算梯度。
    - 只要保证第一步和第二步用的是**同一个教师模型**（即“教师一致性”），这个对比就是合理且没有偏差的。

---

### 一句话总结时间线

| 阶段       | 谁在工作                                    | 产生什么数据                                    | 目的                                    |
| :--------- | :------------------------------------------ | :---------------------------------------------- | :-------------------------------------- |
| **1. SFT** | 教师模型（生成/存概率）<br>学生模型（学习） | 教师的标准答案 + <br>**教师 token 级 log 概率** | 把 Base Model <br>变成能做题的 SFT 模型 |
| **2. OPD** | **只**有学生模型（训练）                    | 学生自己想的答案                                | 把 SFT 模型<br>**强化蒸馏**成推理高手   |

标准 OPD 在阶段 2 还需要教师实时打分。
**Lightning OPD 在阶段 2 直接复用阶段 1 已经存好的教师数据，彻底不需要实时教师了。**
