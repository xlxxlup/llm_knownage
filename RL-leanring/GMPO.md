> **论文标题**：Geometric-Mean Policy Optimization
> **作者**：Yuzhong Zhao 等（中国科学院大学 & 微软亚洲研究院）
> **发布时间**：2025年7月（arXiv: 2507.20673）
> **代码**：[github.com/callsys/GMPO](https://github.com/callsys/GMPO)

---

## 一、研究背景与动机

### 1.1 GRPO 的成功与痛点

近年来，强化学习（RL）在提升大语言模型（LLM）推理能力方面取得了显著成效。其中，**组相对策略优化（Group Relative Policy Optimization，GRPO）** 是一个代表性方法——它在 DeepSeek-R1 等模型中的成功应用，使其受到广泛关注。

GRPO 的核心做法是：对模型生成的一组回复，计算每个 token 的奖励，然后**优化这些 token 级奖励的算术平均值**。它相比传统 PPO 更加高效，且不需要额外的价值模型。

然而，GRPO 存在一个显著缺陷：**算术平均对异常值极其敏感**。在训练过程中，某些 token 可能出现极端的“重要性采样比率”（importance sampling ratio，即当前策略与旧策略对同一 token 的采样概率之比），这些异常值会主导整个更新方向，导致策略更新不稳定。

虽然 GRPO 引入了“剪切”（clipping）操作来缓解问题，但这并未从根本上解决不稳定性，反而过度限制了模型的探索能力，影响泛化性能。

### 1.2 核心思路：从算术平均到几何平均

针对上述问题，本文提出了 **几何平均策略优化（Geometric-Mean Policy Optimization，GMPO）**。核心改动非常简洁：**将 GRPO 中的算术平均替换为几何平均**。

为什么是几何平均？因为几何平均天生对异常值具有更强的鲁棒性——它会相对抑制极端值的影响，从而使训练过程中的重要性采样比率保持在一个更稳定的范围内。

---

## 二、方法详解

GMPO 的设计原则十分明确：**几乎只做一件事——把算术平均换成几何平均**，但这次替换带来了连锁的正面效应:

1. **更稳定的重要性采样比率**：由于几何平均抑制了极端 token 的贡献，训练过程中的重要性采样比率波动大幅减小。
2. **更好的梯度性质**：作者从理论层面证明，GRPO 和 GMPO **都可以写成加权策略梯度的形式**，区别在于——GRPO 中每个 token 的梯度受到自身重要性采样比率的加权，容易受极端值影响；而 GMPO 中每个 token 的梯度则受到整条序列重要性采样比率几何平均的加权，更新更加平滑稳定。
3. **防止策略过早坍塌**：由于更新更稳定，模型在训练过程中保持了**更高的策略熵**和**更低的 KL 散度**，这意味着政策的多样性更高，探索能力更强，不容易过早陷入确定性策略。

此外，GMPO 在具体实现上还有一个细节选择：不同于 DeepSeek-R1 在序列级别做剪切，GMPO 延续 DeepSeek-Math 的做法，**在 token 级别进行剪切**。作者通过实验说明 token 级剪切比序列级剪切更加稳定。

---

## 三、核心贡献

| 维度             | GRPO                      | GMPO               |
| ---------------- | ------------------------- | ------------------ |
| 优化目标         | 算术平均                  | **几何平均**       |
| 对异常值的敏感度 | 高（易被极端 token 主导） | **低（天然鲁棒）** |
| 重要性采样比率   | 波动大，不稳定            | **波动小，稳定**   |
| 训练动态         | 容易过拟合/过早收敛       | **保持探索能力**   |
| 实现改动         | —                         | **即插即用**       |

**一句话总结**：GMPO 几乎不用改 GRPO 的整体框架，只是把平均方式从“加法平均”变成“乘法平均”，就获得了显著更稳定的策略更新——堪称给 RL 训练装上了“防抖器”。

---

## 四、实验与结果

作者在多个数学推理基准上进行了评估，主要发现包括：

### 4.1 主要性能提升

在 GMPO-7B 上，相比 GRPO：
- **数学推理基准**（AIME24、AMC、MATH500、OlympiadBench、Minerva、Geometry3K 等）：
  - **平均 Pass@1 提升最高达 4.1%**
- **多模态推理基准**：
  - **平均提升 1.4%**
- **超越了多项 SOTA 方法**

这意味着 GMPO 不仅在稳定性上优于 GRPO，在最终性能上也实现了显著的提升——更稳的同时也更准。

此外，作为第三方佐证，后续工作 APMPO（Adaptive Power-Mean Policy Optimization）在研究综述中也明确指出：“GMPO 使用几何平均作为目标函数来抑制异常奖励的负面影响，但单一的低奖励会急剧拉低几何平均，导致 GMPO 倾向于丢弃那些有前景但不稳定的推理路径”。这从侧面印证了 GMPO 的方法得到了学术界的关注与认可。

## 五、创新点与不足

### 创新点
1. **极简而有效的设计**：只改了一个聚合函数（算术平均 → 几何平均），实现了“即插即用”的稳定性提升。
2. **扎实的理论分析**：从策略梯度的角度证明了 GMPO 具有更稳定的加权机制。
3. **全面的实验验证**：覆盖多个数学推理基准，充分展示了 GMPO 的优势。

### 潜在不足
1. **对低奖励过于敏感**：几何平均的性质意味着，如果某个 token 的奖励趋近于 0，整个乘积会急剧缩小——这可能导致模型对“有风险但有前景”的推理路径过于保守。
2. **应用范围相对有限**：目前实验主要聚焦于数学推理任务，其方法在更广泛的任务（如开放域对话、创意写作等）上的效果尚未充分验证。

## 六、总结与启示

GMPO 是一篇**思路清晰、方法简洁、理论扎实、实验充分**的工作。它敏锐地发现了 GRPO 中“算术平均对异常值敏感”这一核心问题，并用一个非常简练的解决方案——“换成几何平均”——从根本上改善了 RL 训练的稳定性。

对于实际应用者而言，这篇论文的启示在于：**在强化学习微调 LLM 时，聚合函数的选择对训练稳定性和最终性能有深远影响**。GMPO 的“即插即用”特性也意味着它可以很方便地集成到现有的 GRPO 训练流程中，值得尝试。

### 1. 什么是几何平均？GMPO 里具体怎么算？

**定义：**
对于一组正数 $ x_1, x_2, \dots, x_n $，它们的**几何平均** $ G $ 定义为：
$$
G = \left( \prod_{t=1}^{n} x_t \right)^{\frac{1}{n}} = \sqrt[n]{x_1 \cdot x_2 \cdots x_n}
$$
或者写成对数形式更方便计算：
$$
\log G = \frac{1}{n} \sum_{t=1}^n \log x_t
$$
这意味着 **“取对数后做算术平均，再指数回来”**。

**本质区别：**
算术平均是“加和平均”，对极大值敏感（一个异常大值会显著拉高均值）；几何平均是“连乘平均”，对极小值更敏感（一个接近 0 的项会让整体急剧变小），但它同时会压缩极端高值和低值的差距，让整体更“中庸”，从而抑制异常值的统治力。

**GMPO 中怎么用：**
GRPO 的目标是最大化每个 token 奖励的**算术平均**。GMPO 则将这个聚合算子直接替换为**几何平均**。具体来说，对于一条长度为 $ T $ 的生成序列，每个 token 位置上都会有一个经过裁剪后的“重要性加权项”，记作 $ c_t(\theta) $（比如 $ \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon) \cdot A_t $ 等形式，后文会详述）。

- **GRPO 的序列目标**（简化形式）：最大化 $\frac{1}{T}\sum_t c_t$
- **GMPO 的序列目标**：最大化 $\left( \prod_t \big(c_t\big) \right)^{1/T}$，其中每个 $ c_t $ 通常为正（可利用优势加权等方式保证）。

在实际实现中，为了数值稳定，GMPO 实际优化的是对数形式：
$$
\mathcal{J}_{\mathrm{GMPO}} = \exp\left( \frac{1}{T} \sum_{t=1}^T \log \big( \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon) \cdot |A_t| \cdots \big) \right)
$$
（这里根据优势正负做了拆分，但总体思路就是 **“先 log，再平均，再 exp”**。）

### 2. GRPO 的 clip 到底是 token 级别还是序列级别？DeepSeek‑R1 用的是哪一种？

这是个很关键的工程细节，容易混淆。我把不同变体给你理清楚：

- **原始 GRPO（DeepSeekMath, 2024）**：使用 **token 级裁剪**。  
  它把每个 token 的重要性比率 $ r_t(\theta) = \frac{\pi_\theta(a_t|s_t)}{\pi_{\mathrm{old}}(a_t|s_t)} $ 单独拿出来，对每一个 token 做 clip 操作，然后取 token 级的算术平均作为目标。

- **DeepSeek‑R1 中的 GRPO （2025）**：使用 **序列级裁剪**。  
  它先算出整条序列的“平均重要性比率”（或整个序列的总概率比），然后再对这个序列级的值进行 clip。相当于把“平均或求和”操作挪到了 clip 外面。

- **GMPO 的选择**：沿袭 DeepSeekMath 的做法，回到 **token 级裁剪**。  
  原因在论文中也有说明：token 级裁剪能让梯度更新更细致，再配合几何平均，稳定性比序列级裁剪更好。

所以我报告中说的 “DeepSeek‑R1 使用的是序列级别的裁剪” 是准确的，而你印象中的 “GRPO 是 token level clip” 指的是 DeepSeekMath 版本的 GRPO。两者确实是同一个框架的不同裁剪粒度变体，GMPO 采用 token 级，这与 DeepSeek‑R1 的实现不同，但得到了更好的稳定性。

### 3. 从公式角度，GMPO 具体怎么对 GRPO 改进的？

我们把两个算法的目标函数拆开看，就能清晰地看见“改进点”。

为简化讨论，假定一组内有多个输出，取其中一条序列。考虑 **token 级裁剪**的形式。

**GRPO 的目标（每条序列的 token 平均）**  
每个 token 有一个优势值 $ A_t $（由组内奖励标准化得到），重要性比率 $ r_t = \frac{\pi_\theta(a_t|s_t)}{\pi_{\mathrm{old}}(a_t|s_t)} $。GRPO 最大化：
$$
\mathcal{J}_{\mathrm{GRPO}} = \frac{1}{T} \sum_{t=1}^{T} \min\Big( r_t A_t,\; \text{clip}(r_t, 1-\epsilon, 1+\epsilon) A_t \Big)
$$
这个式子里，每个 token 的贡献与它自己的 $ r_t $ 和 clip 后的值成正比。当某个 token 的 $ r_t $ 非常大（策略突变），这一项的绝对值就会主导整个求和，使更新方向被这个异常 token 带偏。

**GMPO 的目标（几何平均，token 级裁剪）**  
GMPO 不求和，而是连乘：
$$
\mathcal{J}_{\mathrm{GMPO}} = \left[ \prod_{t=1}^{T} \text{clip}\big( r_t,\; 1-\epsilon, 1+\epsilon \big)^{A_t} \right]^{\frac{1}{T}}
$$
为处理优势可能为负的情况，实际实现中通常会拆成 $ A_t>0 $ 和 $ A_t<0 $ 两部分，并使用 $ |A_t| $ 作为指数，但核心思想不变：**每个 token 的贡献是以 clip 值为底、优势为指数的形式，再求几何平均。**

我们对上式取对数，就得到一个非常直观的对比形式：
$$
\log \mathcal{J}_{\mathrm{GMPO}} = \frac{1}{T} \sum_{t=1}^{T} A_t \cdot \log\Big( \text{clip}(r_t, 1-\epsilon, 1+\epsilon) \Big)
$$
而 GRPO 的对数形式并不是这样（GRPO 没有严格的全局对数拆解关系），但我们可以对比梯度的差异：

- **GRPO 的梯度**（简化表示）：
  $$
  \nabla_\theta \mathcal{J}_{\mathrm{GRPO}} \approx \frac{1}{T} \sum_{t} A_t \cdot \text{clip}'(r_t) \cdot \nabla_\theta \log \pi_\theta(a_t|s_t)
  $$
  每个 token 的梯度前面乘的是 **该 token 自己的裁剪比率相关项**，因此 $ r_t $ 异常大的 token 直接会在梯度中获得巨大的权重。

- **GMPO 的梯度**（推导后）：
  $$
  \nabla_\theta \mathcal{J}_{\mathrm{GMPO}} \approx \mathcal{J}_{\mathrm{GMPO}} \cdot \frac{1}{T} \sum_{t} \frac{A_t}{\text{clip}(r_t)} \cdot \text{clip}'(r_t) \cdot \nabla_\theta \log \pi_\theta
  $$
  更重要的是，在进一步整理后，会发现每个 token 的梯度权重并非仅由自身决定，而是被 **整条序列的几何平均** 所平滑。极端 token 的 clip 值对整体对数和的贡献被严重抑制（因为 log 函数的压缩效应），使得单点异常无法大幅拉偏整个更新方向。

**一句话总结改进：**  
GRPO → GMPO，就是把所有 token 的贡献从 **“求和受异常值支配”** 变成了 **“先 log 压缩异常值，再求和，再恢复尺度”**。这个简单的算子替换，从根源上消减了重要性比率峰值带来的梯度噪声，让策略更新变得异常稳健。
